# 01 环境与数据：快速上手

## 环境

本项目实际运行环境（供对照）：

| 项 | 版本/说明 |
|---|---|
| OS | Windows 11 中文版（坑最多的一种，见下表） |
| Python | 3.14.3（requirements.txt 锁定直接依赖） |
| 核心库 | numpy / pandas / matplotlib / scikit-learn / scipy / h5py / lifelines |
| 编辑器 | Spyder（逐格跑大脚本） |

安装已验证环境的直接依赖：

```bash
python -m pip install -r requirements.txt
```

> 环境哲学：复现结果绑定于已验证的 Python/依赖版本；本仓库锁定直接依赖。升级库版本前先跑 CI 与固定划分测试，不要把“最新版”自动当成“可复现”。

## 数据

### MIT-Stanford 数据集（主数据，8.3GB）

- 来源：Severson et al. 2019 官方（原论文 Data availability；GitHub: rdbraatz/data-driven-prediction-of-battery-cycle-life-before-capacity-degradation）
- 文件：3 个 .mat（MATLAB v7.3 = HDF5 格式）：`2017-05-12_batchdata_updated_struct_errorcorrect.mat`、`2017-06-30_batchdata_updated_struct_errorcorrect.mat`、`2018-04-12_batchdata_updated_struct_errorcorrect.mat`
- 默认放置：`data/mit/`；若另存他处，在根目录 `config.toml` 的 `paths.mit_dir` 设置目录。

### NASA PCoE 电池数据集（迁移用）

- 来源：NASA Prognostics Data Repository 的 Battery Data Set
- 文件：34 个平铺 .mat（B0005~B0056，含官方抽取包与全量包两种；本仓库脚本默认全量平铺版）
- 默认放置：`data/nasa/`；若另存他处，在 `config.toml` 的 `paths.nasa_dir` 设置目录。

配置步骤：复制 `config.example.toml` 为 `config.toml`，按实际位置修改数据目录；配置文件不会提交到 Git。运行 `python scripts/run_project.py --show-paths` 检查最终解析路径，也可用 `BATTERY_MIT_DIR`、`BATTERY_NASA_DIR` 等环境变量临时覆盖。

### 运行与缓存行为

| 路线/脚本 | 数据需求与运行行为 |
|---|---|
| `--stage quick` | 不需要原始数据；运行合成玩具树模型并输出一张教学图。 |
| `step1`–`step3` | 使用 NASA 教学电池；不需要 MIT 8.3GB 数据。 |
| `step4_mit_load.py`、`step4_2_mit_features.py`、`step4_3_rf_predict.py`、`step4_3b/c` | 为保持单脚本教学性，每次从 MIT 原始 `.mat` 自行解析；多次运行会重复读数据，耗时取决于磁盘和机器。 |
| `step4_3f_official_split.py` | 首次解析后创建 `.cache/mit_parse_cache.pkl`；后续 5b/5c/step6 可复用此缓存。模型搜索仍需数分钟。 |
| `step5a` | 解析完整 NASA 34 文件并生成本地审计缓存。 |
| `extensions/full` | 需要 NASA 34 个 `.mat`；`full` 会运行多个自包含脚本并重复解析，适合教学，不是最快的批处理方式。 |

开始前用 `python scripts/run_project.py --show-paths` 查看实际目录；缺数据时 runner 会在开跑前提示缺少哪些文件。

数据就绪后可用 `python scripts/run_project.py --stage paper` 复现主结果；`--stage extensions` 跑 NASA 扩展，`--stage optimization` 跑 step6。首次体验可运行无数据的 `--stage quick`。

## 已知坑表（本项目实际踩过、已修复的）

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | 中文 Windows + sklearn 富显示 | `UnicodeDecodeError: 0x94`（GBK 撞 UTF-8） | `sklearn.set_config(display="text")`；`.fit()` 单独成行，不留格尾表达式 |
| 2 | 最新 sklearn 删参数 | `TypeError: n_alphas is unexpected` | 用最小参数集；查 `sklearn.__version__` 对照文档 |
| 3 | 8.3GB 解析静默几分钟 | 像"卡死"，忍不住重跑 → 内核堆积越跑越慢 | 解析加 pickle 缓存 + 进度打印（`flush=True`）；重跑前先杀干净 python.exe |
| 4 | MATLAB v7.3 的 HDF5 引用 | KeyError / 看不懂的嵌套 | 逐层解引用；MATLAB 1-based 偏移用探针验证 |
| 5 | Jupyter 重跑堆积 | 同名输出、变量串台 | Restart Kernel 逐格跑；重活写成 .py |

更细的现场版（含每一次完整报错与修复过程）见 `docs/05_调试实录.md`。

## 目录结构约定

```text
battery-lifetime-guide/
├── .github/    # CI（无原始数据也可运行）
├── .cache/     # 本机解析缓存，不入 git
├── config.toml # 本机数据路径，可从 config.example.toml 复制，不入 git
├── data/       # README 入库；mit/、nasa/ 原始数据不入 git
├── results/    # 已核验快照入库；generated/ 本机新产物不入 git
├── scripts/    # 教学脚本、统一配置和 run_project.py
└── tests/      # 标签与路径配置测试
```

> 大文件（.mat/.pkl）、`config.toml` 和 `results/generated/` 不进 git；已核验的小型 CSV/图表快照可以作为证据留在仓库。
