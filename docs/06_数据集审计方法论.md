# 06 数据集审计方法论：任何公开数据集的 5 项体检

> 从阶段 5a 的"电池四道门"抽象出来的通用清单。适用对象：任何打算拿来训练/复现的公开数据集。
> 核心思想一句话：**标签的质量决定一切——而公开数据集的 README 不为你的标签负责。**

## 原则

1. **逐个实体体检，不看汇总统计**——均值和总数会掩盖 NASA 中 11 颗测试中断井这类致命个体；MIT 的 5 颗则是另一种续跑标签问题；
2. **每道检查对应一个真实坏例子**——没有坏例子的检查是装饰；
3. **分类宁误杀不放过**——把 B0033 标"边界"损失 1 颗，把井标"寿命 42"毒化整个训练集；
4. **审计结果本身是一张表**——每颗/每条的类别、依据、放行与否，进版本库（参照 NASA34颗体检分类.csv）。

## 5 项检查

| # | 检查 | 问的问题 | 本项目对应 |
|---|---|---|---|
| 1 | **完整性** | 实体数、字段数、缺失模式对得上 README 吗？ | 138→124 颗（官方剔除）；NASA 平铺 34 颗 vs 官方抽取包 |
| 2 | **物理可行性** | 每条记录在领域常识下可能吗？ | 容量回弹、单圈跳变（解析伪影 vs 真实再生） |
| 3 | **事件完整性** | 关键事件（EOL/故障）真的发生并记录了吗？ | 11/34 删失——"没测到死"的电池不能当"死了"用 |
| 4 | **协议一致性** | 全程同一实验协议吗？协议变更点在哪？ | B0033 起随机化工况；删失刻度两段=两个测试批次 |
| 5 | **标签可提取性** | 按你的定义，标签真正可算的实体有几个？ | **3/34**——README 说"循环寿命数据集"，实际 3 颗 |

## 第 5 项的一个推论（最容易被跳过）

"官方数据集"四个字 ≠ "官方标签都成立"。MIT 124 颗几乎全部可提取标签（协议统一、测到死），NASA 34 颗只有 3 颗——**同一句话在两个数据集上的含金量差 40 倍**。拿到数据先算这个分母，它决定你后面所有实验的样本量上限。

## 审计之后的三个去向

- **标签成立** → 进训练/测试（仍要留官方剔除名单这道闸，见 docs/05 案例 9）；
- **删失** → 生存分析（不要扔、不要当真，见 04 §5d）；
- **异常** → 分类归档，写明依据；异常样本常常是**新研究问题的入口**（中断井 → 测试协议历史；抖动 → 随机化工况 → 5c 的定罪主犯）。
