# 11 实习求职包装指南：从"做完项目"到"拿到面试"

> 给和你一样处境的人：材料/新能源方向本科生，没有大厂实习，需要一件"能证明工程能力与科学素养"的作品。
> 本文档回答四个问题：项目怎么完成 / 如何把复现发展成自己的工作 / 简历上怎么写 / 面试怎么讲。
> 配套：技术追问见 `10_面试问答卡.md`；本文只管"讲与写"。

---

## 一、这个项目实际是怎么完成的（过程复盘，全部真实）

### 1.1 项目的时间结构

这不是"闭关一个月"的项目，而是**深度优先、随课推进**的结构：每个阶段 1~2 个集中工作日，中间隔课程日常。总日历跨度约一个月（2026-10 中旬从零到 repo v1），纯工作时长集中在几个长夜。

**给你的启示**：作品集项目不需要整块时间，需要**可中断的阶段边界**——每阶段有明确的"完成标准"（本项目的标准：脚本跑通+图落盘+数字进记录 md），中断不丢上下文。

### 1.2 阶段划分的逻辑（可借鉴，不要照搬结论）

由小到大，每一步都在为下一步积累"已验证的积木"：

```
模拟数据(无风险) → NASA 4颗(肉眼可查) → 指纹原理(单图)
→ MIT 124颗(全量+官方考卷) → 跨数据集(论文没有的原创空间)
```

关键决策：**先复现再做个人扩展**。复现给出可对照基线；扩展实验建立在可信管线之上。你可以借鉴阶段结构，但应换成自己能说明来源的数据和研究问题，不能把本仓库的代码/数字改名后说成独立原创。

### 1.3 双 AI 交叉审计工作流（面试会被问，值得讲清楚）

本仓库记录的实际分工：

- **AI-A（出题人+实现者）**：写脚本、修 bug、写文档；
- **AI-B（独立管道）**：不看 AI-A 的代码，独立实现同一条管线；
- **人（裁判）**：跑两边代码，比对数字，逐位一致才算复现成立；两边结论冲突时，设计实验裁决（归因链四轮就是这么来的）。

**为什么这个工作流本身就是加分项**：它演示了"AI 产出、人类验证"的工作方式——关键数字通过独立管道和人工检查。若你复用此流程，简历/README 应写清楚你实际承担的实现、判断和验证工作，不要把本仓库的分工自动说成自己的经历。

### 1.4 Debug 文化（这个项目最值钱的遗产）

规则三条：**修复版存新文件（v1/v2）、错误逐条留痕（现象→根因→修复）、buggy 版本带注释保留**。产出：15+ 项错误清单、4 个事故现场教学文件、一份"带毒结果差点过审"的实录。

这套东西的作用：面试里任何"你遇到最大的困难是什么"都有具体弹药——不是"我学会了坚持"，是"我通过 CV MAE 0.135 这个异常信号，发现了 5 颗电池标签全是 1 圈"。

## 二、简历怎么写（可直接粘贴的模板）

### 2.1 三条 bullet 基础版（技术岗通用）

```text
锂电池循环寿命预测项目（个人项目，复现 Severson et al. Nature Energy 2019）   2026.10
· 复现论文管线（ElasticNet/RandomForest，ΔQ(V) 六特征），官方划分口径中位误差
  5.9% [CI 5.1~8.9]；论文点估计为 9.1%，论文侧无可比 CI，因此不判断统计一致或优劣；
· 通过四轮误差归因将首跑 33.6% 降至 5.9%：定位并修复标签污染（0 占位符）与
  pandas iterrows 写回缺陷，建立"合并生效断言"防回归机制；
· 对 NASA 数据集 34 颗电池逐颗审计，证明寿命标签仅 3/34 成立；以可证伪实验
  排除窗口/标签假设，将跨数据集失效归因于协议级非平稳性；Kaplan-Meier 处理
  11 颗删失电池，估计中位寿命 125 圈。
```

要点：**动词开头、数字进 bullet、括号给上下文**。"复现+归因+原创"三层结构对应"会用工具、会 debug、会做研究"三种能力。

### 2.2 按岗位换弹头

| 目标岗位 | 改写重点 |
|---|---|
| 电池厂研发/测试 | 强调 EOL 定义、删失处理、协议非平稳性——这些是测试岗位日常（测到死/没测到死/工况变更） |
| 半导体工艺/检测 | 强调数据审计、良率思维（3/34 可用=数据质量决定分析上限）、管线自动化与缓存 |
| 数据分析/算法 | 强调特征重要性 0.92、地板效应（模型选择=分布匹配）、bootstrap CI、误差归因方法论 |
| 质量工程师 | 强调断言防回归、双管道交叉验证（这就是 SQE 的复测思维） |

### 2.3 诚信边界（面试官一戳就破的东西别写）

- 不写"提出并证明了协议非平稳性理论"——你的贡献是**实验归因**，不是理论证明；
- 不隐去 AI 协作——被问到就大方讲 1.3 的工作流，藏着掖着被抓到才是致命的；
- 5.9% vs 9.1% 不说"统计一致"或"超越"——论文侧无同口径 CI，准确说法是"点估计接近，统计差异未定"。

## 三、面试怎么讲

### 3.1 三分钟项目叙述模板（背下来，不是念稿）

```text
【是什么】(20s) 论文用前100圈的放电数据预测电池寿命，MIT 数据集124颗。
我在官方划分口径下复现到中位误差5.9% [5.1,8.9]，论文点估计9.1%；论文侧没有可比CI，因此只说点估计接近，不判断统计一致或优劣。

【难点在哪】(40s) 最大的困难不是模型——首跑33.6%，但模型没问题。我做了
四轮归因：调参排除、考卷口径排除、最后发现是标签被污染：续跑电池的第1圈
是0占位值，重算寿命时5颗电池标签全变成了"1圈"。

【怎么发现的】(40s) 两个信号：诊断打印的标签数字反常，CV指标异常跳变。
修复时又踩了pandas iterrows的副本陷阱——打印全对但下游没生效。这之后我
给所有改标签的操作加了生效断言，与预期值不符直接报错。

【原创部分】(40s) 复现完成后我追问了论文没回答的问题：换数据集标签还成立吗？
审计发现NASA 34颗里只有3颗标签可用；零样本迁移EN误差×125；用四组可证伪
实验排查窗口与标签口径（标签已排除；窗口切片 v2.1 修复重跑后也排除且反转），
锁定嫌疑"协议级非平稳性"——同样的早期指纹，不同的未来。

【反思】(20s) 这个项目教会我的是：数据驱动项目里，最难的部分不是建模，
是确认"数字为什么是这个数字"。我把15个错误的完整现场留在了repo里。
```

### 3.2 追问应对（压力问题清单）

| 追问 | 应对策略 |
|---|---|
| "这不就是跑了别人的代码？" | 给事实：六特征自实现、归因链修复的 bug 有普遍参考价值、阶段 5 全是论文没有的实验；证据=repo 的调试实录 |
| "主要工作是不是 AI 做的？" | 讲 1.3 工作流：人做裁决与验证，双 AI 独立路径互验；反问对方团队怎么处理 AI 代码的 review——把话题引到工作流管理能力 |
| "为什么不用深度学习？" | 124 颗样本 + 已有可复现基线 + 划分一致性要求；方法论顺序："先小模型归因，再考虑大模型" |
| "5.9% 比 9.1% 好，说明你比作者强？" | 不能这么推断：论文侧没有同口径 CI/逐颗误差；只报告本复现的 CI，并说点估计接近、统计差异未定 |
| "这项目对你的材料专业有什么用？" | dQ/dV 三指纹对接正极 LAM 机理；数据审计思维可迁移到实验数据管理（你的 SCLC 数据同样需要） |

### 3.3 没人问技术时的引导话术

- 面试官泛泛问"做过什么项目"→ 直接用 3.1 模板，讲完主动说"repo 里有完整的调试实录，最有意思的是 XX 案例"——把战场拉到你准备过的地方；
- 被问到不会的 → "这个我没做过，但做 SOH 项目时遇到过类似结构的问题，当时的处理是……"——用已验证的素材垫，不空手接白刃。

## 四、投递组合拳（一致性检查清单）

上线前逐项打勾：

- [ ] **简历 bullet 的每个数字**都能在 repo 的 results/ CSV 里找到出处；
- [ ] **GitHub README 首屏**：成绩单表 + 一句定位（"带事故现场的复现攻略"）；
- [ ] **一页 PDF**（可选加分项）：项目一页纸报告——摘要图 + 成绩单 + 归因链简图；
- [ ] **repo 链接放简历右上角联系方式区**，不用短链；
- [ ] **GitHub 主页 pinned** 该 repo，主页 bio 与求职方向一致；
- [ ] 面试当天能**离线复述**：三分钟模板 + 归因链四轮 + 5 组核心数字（5.9%[5.1~8.9]/9.1%、33.6%→5.9%、3/34、×125、125 圈）。

> 最后一条建议：这个项目上线后，**每周看一次自己 repo 的 commit 记录**——面试官问"最近在做什么"，你永远有新答案。

## 五、练习：从复现做出个人项目

目标不是复制本仓库后改名，而是用它练习一套可迁移的研究/工程流程，并留下能证明自己贡献的产物。

### 练习步骤

1. **先复现**：用 `python scripts/run_project.py --stage paper` 跑官方基线，保存自己的环境、路径配置和运行记录；若只引用仓库已有结果，要明确说是仓库提供的结果。
2. **提出自己的问题**：例如某个特征窗口是否影响误差、另一批次能否迁移，或在你有权使用的电池数据上能否复现同一规律。不要把未来的通用审计工具计划写成已完成能力。
3. **事先写判据**：记录假设、数据来源/许可、标签定义、训练/验证/测试划分、主指标和什么结果会否定假设；不能看测试结果再选特征或改口径。
4. **完成一个可辨认的新增贡献**：新实现、新数据或有证据的负结果均可；加入一个针对新增逻辑的测试，并将脚本、逐样本结果、结论和限制一起提交。
5. **整理个人作品页**：列出上游来源、本人的改动、复现结果与个人扩展的区别、AI 工具参与了什么，以及如何从干净环境运行。

### 交付清单

- `research_question.md`：问题、假设、预先确定的判据；
- `data_manifest.md`：来源、版本、许可、文件清单和获取方式（不提交受限原始数据）；
- `results/`：可复算的逐样本预测/指标及置信区间；
- `tests/`：至少覆盖新增行为的自动测试；
- `README.md`：复现命令、个人贡献、AI 使用说明和限制。

简历 bullet 可按“基于【来源论文/项目】复现【基线】；我新增【具体方法/实验】，在【预先声明的划分】上得到【可复算结果与区间】；发现【限制/负结果】”组织。方括号内容必须替换成你亲自完成且能从仓库验证的事实；不得把上游贡献或本仓库既有数字写成自己的独立原创结果。
